# Running Hearthstock on an iPhone

You do this once per Mac and phone. After that, any build goes to the phone with Run.

## Why the team ID isn't in Xcode's Signing tab

`Hearthstock.xcodeproj` is generated by XcodeGen and gitignored. Anything you pick in Xcode's
Signing & Capabilities tab is lost the next time `xcodegen generate` runs. Signing is set in
files instead:

- `Config/Signing.xcconfig` (committed) turns on automatic signing and includes `Local.xcconfig` if it exists.
- `Config/Local.xcconfig` (gitignored) holds your `DEVELOPMENT_TEAM`. Copy `Config/Local.xcconfig.example` to create it.

Without `Local.xcconfig`, the app still builds and runs on the simulator.

## One-time setup

1. **Apple ID in Xcode.** Xcode → Settings → Accounts → + → Apple Account. Your team appears under
   it. Its team ID is the 10 characters that go in `Config/Local.xcconfig`.
2. **Team ID.** Copy `Config/Local.xcconfig.example` to `Config/Local.xcconfig`, set
   `DEVELOPMENT_TEAM`, then run `xcodegen generate`.
3. **Connect the phone.** Plug it in with a cable and unlock it. Tap **Trust** on the "Trust This
   Computer?" prompt and enter the passcode. In Xcode, Window → Devices and Simulators should list
   the phone. The first time, Xcode spends a minute or two preparing it for development.
4. **Developer Mode on the phone.** Settings → Privacy & Security → Developer Mode → on. The phone
   restarts. After unlocking, confirm **Turn On**. The switch only appears once the phone has been
   connected to Xcode, so do step 3 first.
5. **Run.** In Xcode, choose the phone as the run destination and press Run (⌘R). The first build
   registers the phone and the app's bundle ID with your team and creates a development profile.
   That's why it needs your Apple ID signed in.

From the command line, with the phone connected:

```sh
xcrun devicectl list devices            # note the phone's identifier, for devicectl
xcodebuild -project Hearthstock.xcodeproj -scheme Hearthstock -showdestinations   # the phone's id here (its hardware UDID) is the one xcodebuild needs
xcodebuild -project Hearthstock.xcodeproj -scheme Hearthstock \
  -destination 'platform=iOS,id=<identifier>' -allowProvisioningUpdates build
```

## How long a build lasts

- **Paid Apple Developer Program team:** the development profile lasts a year. Re-running from
  Xcode renews it.
- **Free (Personal Team) account:** the app stops launching after 7 days. Run it again from
  Xcode to re-sign it. You can have at most 3 apps installed this way at a time.

## Keeping the data

The database lives in the app's container. Rebuilding and running again keeps it, as long as the
bundle ID stays the same. Deleting the app from the phone deletes the data, so export a backup
from Settings first.

## If something goes wrong

- **"No Account for Team" / "No profiles for '…' were found":** the Apple ID isn't in Xcode, or
  `DEVELOPMENT_TEAM` doesn't match it. Check step 1 and step 2, then run `xcodegen generate`.
- **"Your team has no devices from which to generate a provisioning profile":** the phone isn't
  connected or isn't trusted yet (step 3).
- **"Developer Mode disabled":** see step 4.
- **"Failed to register bundle identifier" / "not available":** someone else already uses that
  bundle ID. Pick a different one in `project.yml`.
- **"Untrusted Developer" when opening the app:** Settings → General → VPN & Device Management →
  your Apple ID → Trust.
- **The phone shows as unavailable or busy in Xcode:** unplug it, unlock it and plug it in again.
  Leave it connected while Xcode copies the debug symbols.
